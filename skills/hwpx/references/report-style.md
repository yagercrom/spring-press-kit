## 1. 문서 구조

보고서는 공문(기안문)과 달리 다음 구조를 갖는다:

```
1쪽: 표지
  ├─ 상단: 기관 로고/장식 테이블
  ├─ 중앙: 보고서 제목 (30pt, 25pt HY헤드라인M, 가운데 정렬)
  └─ 하단: 작성일 (25pt HY헤드라인M)

2쪽: 목차
  ├─ 장식 배너 테이블 (색상 그라데이션)
  ├─ "목  차" 타이틀 (28pt HY헤드라인M)
  └─ 목차 항목 (로마 숫자 Ⅰ~Ⅴ + 제목 + 페이지)

3쪽~: 본문
  ├─ 결재란 테이블 (3x3, 페이지 상단)
  ├─ 보고서 제목 (22pt HY헤드라인M, 가운데 정렬)
  ├─ 섹션 구분 바 (1x3 색상 테이블)
  └─ 본문 계층 구조 (□ → ○ → ― → ※)
```

## 4. 항목 기호 체계

보고서에서는 공문서 번호 체계(1. 가. 1) …)가 아닌 **기호 체계**를 사용한다:

```
1단계:  □    (HY헤드라인M 16pt, 문단 위 15)
2단계:  ○    (휴먼명조 15pt, 문단 위 10)
3단계:  ―    (휴먼명조 15pt, 문단 위 6)
4단계:  ※    (한양중고딕 13pt, 문단 위 3)
```

### 작성 예시

```
 □ 2026년 AI 기술 도입 현황 분석 결과
  ○ 전년 대비 도입률 23% 증가
   ― 공공기관 도입률: 45.2% (전년 36.8%)
     ※ 교육청 및 산하기관 포함 수치
  ○ 주요 도입 분야
   ― 행정업무 자동화: 전체의 58%
   ― 민원 상담 챗봇: 전체의 27%
     ※ 나머지 15%는 데이터 분석 및 기타
```

### □ 기호의 이중 run 구조

XML 내부에서 □ 항목은 두 개의 run으로 구성된다:
- **run 1**: `□` 기호 자체 (13pt, 작은 크기)
- **run 2**: 본문 텍스트 (16pt, HY헤드라인M)

이 이중 구조 때문에 □ 본문을 치환할 때 기호 run은 건드리지 않아야 한다. 실측 결과 `' □ '` 는 본문과 분리된 텍스트 노드로 8회 나온다(10절 참조).

## 5. 섹션 구분 바 테이블

보고서의 대단원(Ⅰ, Ⅱ, Ⅲ …)을 구분하는 디자인 요소. 1행 3열 테이블로 구성된다.

│ 남색 배경  │  │ 연회색 배경, 상하 회색 테두리      │
│ 흰색 글자  │  │                                  │

| 셀 | 너비(HWPUNIT) | 내용 | 배경색 | 글자색 | 글꼴/크기 |
|----|-------------|------|--------|--------|----------|
| 0 | 3327 (~12mm) | 로마숫자 | #193AAA (남색) | #FFFFFF | 휴먼명조 17pt |
| 1 | 848 (~3mm) | (빈칸, 구분선) | 없음 | — | — |
| 2 | 43513 (~153mm) | 섹션 제목 | #F2F2F2 (연회색) | #000000 | HY헤드라인M 17pt |

## 10. 템플릿 기반 활용 패턴

색 배경 셀, 섹션 바, 장식 표는 `header.xml` 의 `borderFill` 정의와 얽혀 있어서 처음부터 만들면 정의까지 같이 만들어야 한다. **`assets/report-template.hwpx` 를 치환해서 쓸 것.**

절차 전체와 함정은 **`template-replacement.md`** 에 있다. 여기서는 이 양식의 실측 데이터만 정리한다.

### 이 양식의 구조 (실측)

- **섹션은 하나다**: 표지·목차·본문이 모두 `Contents/section0.xml` 에 들어 있다. `update_section()` 한 번으로 전부 처리된다.
- 텍스트 노드 67개, 고유 문자열 28개, 반복 문자열 10개.

### 치환 대상 (실측 — `python -m scripts.inspect_template` 결과)

**한 번만 나오는 것** — 그냥 치환한다.

| 원본 텍스트 | 위치 | 치환 대상 |
|---|---|---|
| `브라더 공기관` | 표지 1줄 | 기관명 |
| `기본 보고서 양식` | 표지 2줄 | 보고서 제목 |
| `2024. 5. 23.` | 표지 작성일 | 작성일 |
| `제 목` | 본문 페이지 제목 | 보고서 제목 |
| `Ⅴ` | 목차 5번 | (섹션이 5개 미만이면 삭제) |
| ` [붙 임]`, ` [참 고]` | 목차 하단 | 그대로 두거나 삭제 |
| `  2. 세부내용` | 붙임 2번 | 첨부 목록 |
| ` 추진 배경`, ` 현황 및 문제점` 등 | 섹션 바 제목 | 실제 섹션 제목 |

**여러 번 나오는 것** — `max_count=1` 로 하나씩 채운다.

| 원본 텍스트 | 횟수 | 치환 대상 |
|---|---|---|
| `헤드라인M 폰트 16포인트(문단 위 15)` | 8 | □ 1단계 내용 |
| `  ○ 휴면명조 15포인트(문단위 10)` | 8 | ○ 2단계 내용 |
| `   ― 휴면명조 15포인트(문단 위 6)` | 8 | ― 3단계 내용 |
| `     ※ 중고딕 13포인트(문단 위 3)` | 7 | ※ 4단계 참조 |
| `Ⅰ` `Ⅱ` `Ⅲ` `Ⅳ` | 각 2 | 목차 + 섹션 바 (보통 그대로 둔다) |
| `  1. 세부내용` | 2 | 붙임 1번 + 참고 1번 (**서로 다른 값**) |

> `  1. 세부내용` 이 2회라는 점에 주의. 붙임과 참고에 각각 하나씩이므로 일괄 치환하면 둘이 같은 값이 된다.

### 건드리면 안 되는 것

`' □ '` 가 별도 텍스트 노드로 **8회** 나온다. □ 항목이 두 개의 run(기호 run + 본문 run)으로 구성되기 때문이다(4절 참조). 본문 문자열만 치환하고 이 노드는 그대로 둔다. 치환 목록에 넣으면 기호가 사라진다.

### 부분만 치환해야 하는 것

목차 항목은 값 안에 탭 요소를 품고 있다:

```
'. 개요<hp:tab width="33718" leader="3" type="2"/> 1'
```

`'. 개요'` 만 치환하고 그 뒤는 손대지 않는다. 값 전체를 갈아 끼우면 점선 리더와 페이지 번호가 사라진다.

### 항목 수가 양식과 맞지 않을 때

양식의 □ 자리는 8개다. 내용이 더 많으면 `xml_templates.extract_paragraph_by_pattern()` + `render_paragraph()` + `modify_hwpx.insert_paragraph_after()` 로 문단을 복제한다. 더 적으면 남은 플레이스홀더 문단을 `delete_paragraph()` 로 **뒤에서부터** 지운다 — 앞에서 지우면 인덱스가 밀린다.
