# plan JSON 스키마

`tools/build_press_release.py --plan` 이 받는 구조. 모든 키는 생략 가능하며, 없으면 그 블록이 문서에서 빠진다. 동작하는 전체 예시는 `examples/plan-type-a.json`.

문자열은 **최종 원고 그대로** 넣는다. 생성기는 기호를 붙여 주지 않는다 — `❏`, `■`, `-`, `①`, `※` 를 텍스트에 직접 포함해야 한다. 이렇게 설계한 이유는 유형마다 기호가 다르고(A형 `■ 결과N`, B형 `첫째`, C형 `1.`), 코드가 그걸 추측하면 틀리기 때문이다.

## 최상위 키

| 키 | 타입 | 자리 |
|---|---|---|
| `mail_subject` | string | 첫 줄. `[★태그]`로 시작 |
| `subhead` | string | 부제 / 핵심 메시지 한 줄 |
| `subhead_bullets` | string[] | 부제 보조 항목. 각 줄 `-` 로 시작 |
| `overview` | string[] | `❏` 개요·배경 문단 |
| `overview_box` | string[] | 박스 1 — 조사 개요 |
| `summary_lead` | string | `❏ 그에 따른 주요 분석 결과를 정리하면 다음과 같음.` |
| `summary_box` | string[] | 박스 2 — 결과 요약 |
| `implication_lead` | string | `❏ 본 분석에 따른 시사점은 다음과 같음.` |
| `implication_box` | string[] | 박스 3 — 시사점 |
| `blocks` | object[] | 본문 블록. 아래 참조 |
| `position` | string[] | `■` 기관 입장 문단 |
| `proposals` | string[] | `①`~ 제언 |
| `closing` | string | 마지막 클로징 (존댓말) |
| `publish` | string[] | 발행정보 + 문의. 줄 단위 |

## `blocks[]` — 본문 블록

유형에 따라 `title` 의 기호만 달라진다. 구조는 공통이다.

```json
{
  "title": "■ 결과 1: 핵심 발견 한 줄 요약",
  "paragraphs": ["서술형 해설 문단 (존댓말)"],
  "tables": [
    {
      "caption": "  [표 1] 표 제목",
      "headers": ["구분", "사무직 (27개)", "기술직 (30개)"],
      "rows": [["출신학교", "27개 (100%)", "30개 (100%)"]]
    }
  ],
  "notes": [" ※ 표에 대한 보충 설명"]
}
```

- `title` — A형은 `■ 결과 N: …`, B형은 `첫째 - …`, C형은 `1. …`
- `paragraphs` — 결과 해설. **존댓말**. 문단 사이 빈 줄은 생성기가 넣는다
- `tables` — 생략 가능. `caption` 은 표 **위**에 들어간다
- `notes` — 생략 가능. `※` 로 시작

블록 개수·표 개수에 제한은 없다. 원본 발행본은 결과 6개였지만 그 수에 맞출 필요는 없다.

## 박스 줄 수 제약

`overview_box` · `summary_box` · `implication_box` 는 1×1 테두리 박스이고 줄 수가 원본에 고정돼 있다.

- 적게 주면 → 남는 빈 문단이 자동 삭제된다 (`note:` 메시지 출력)
- 많이 주면 → 초과분이 마지막 줄에 합쳐진다 (`warning:` 메시지 출력)

`warning:` 이 나오면 줄을 합치거나 내용을 `blocks` 로 옮길 것. 경고를 무시하면 마지막 줄이 길게 뭉친 채로 발행된다.

## 빈 줄

`publish` 배열에 `""` 를 넣으면 그 자리에 빈 줄이 들어간다. 서명과 문의처 사이를 띄우는 데 쓴다.

## 흔한 실수

- **기호를 빼먹음** — 생성기는 붙여 주지 않는다. `❏`, `■` 없이 넣으면 그냥 평문으로 나온다.
- **어미를 섞음** — 개요·요약·입장·제언은 명사형, 결과 해설·클로징은 존댓말. SKILL.md의 표 참조.
- **표 캡션을 표 아래에 두려 함** — `caption` 은 항상 표 위에 렌더링된다. 아래에 붙일 주석은 `notes` 를 쓴다.
- **`headers` 와 `rows` 열 수 불일치** — 열 수가 다르면 표가 깨진다. 생성 후 검증에서 표 오류로 잡힌다.
